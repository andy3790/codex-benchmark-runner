# 사용 가이드

이 문서의 명령은 저장소 루트에서 실행합니다. [프로젝트 소개로 돌아가기](../README.md).

## 데스크톱 GUI

Windows에서 `launch_gui.pyw`를 더블클릭하거나 프로젝트 폴더에서 다음 명령을 실행하세요. GUI를 여는 것만으로 모델이 호출되지는 않습니다.

```powershell
python -m codex_bench --gui
```

다른 설정을 열려면 `python -m codex_bench --gui --config C:\bench\config.json`을 사용하거나 창의 **설정 열기**를 누릅니다. `python -m codex_bench.gui`도 지원합니다. 선택적으로 패키지를 설치하면 콘솔 창 없이 실행하는 `codex-bench-gui` 명령을 사용할 수 있습니다. Python 기본 배포판에 포함된 Tkinter를 사용하며 별도 GUI 패키지는 필요하지 않습니다. Tkinter를 제외한 Python 설치나 화면이 없는 서버에서는 기존 CLI를 사용하세요.

왼쪽 탭에서 모델별 추론 강도, 반복/병렬 실행, 경로와 채점기, 시간/출력 한도, 공통 프롬프트를 편집합니다. 모델의 **추가·수정·삭제**와 전체 조합 수 미리보기를 지원합니다. 오른쪽 표에는 완료/실패/실행 중 개수, 각 실행의 점수·토큰·시간을 표시하고, 하단에는 실시간 로그와 선택한 실험의 상세 기록을 표시합니다. 실행 중에도 창은 응답하며, 좁은 창에서는 설정을 스크롤하고 결과·로그 구분선을 조절할 수 있습니다.

| 버튼 | 동작 |
| --- | --- |
| 설정·프롬프트 저장 | 입력을 검증한 뒤 저장. 외부에서 바뀐 파일은 덮어쓰지 않음 |
| 환경 진단 | 로컬 Codex 버전·도움말을 확인. 모델 호출 없음 |
| dry-run | 현재 편집 내용으로 예정 조합과 명령을 표시. 설정/결과 파일을 쓰거나 모델을 호출하지 않음 |
| 모의 실행 · 토큰 0 | 가짜 Python 프로세스와 합성 채점기로 전체 실행·기록·보고서 흐름을 검증. Codex/Docker/후보 코드 실행 없음 |
| 실제 실행 / 재개 | 설정과 프롬프트를 저장하고 기존 실행기로 실행. 이 버튼은 실제 Codex 사용량을 발생시킴 |
| 중단 | 새 작업을 멈추고 실행 중인 프로세스 트리를 종료한 뒤 기록 보존 |
| HTML 보고서 열기 | 최근 생성한 로컬 HTML을 기본 브라우저로 열기 |

다른 프롬프트 파일을 선택하면 선택 시점의 내용을 기준으로 외부 변경을 검사합니다. 선택 후 다른 편집기에서 수정하거나 파일을 삭제했다면 저장을 중단하고 해당 파일과 설정을 보존합니다. 파일 선택 취소는 편집 중인 내용과 변경 감지 기준을 바꾸지 않습니다. 선택한 파일을 편집하지 않고 저장할 때는 기존 BOM·줄바꿈 형식도 유지합니다.

모의 결과는 실제 `output_dir`의 형제 폴더 `<output_dir 이름>-mock/demo-<ID>/output/`에 저장됩니다. 공개 기본 설정에서는 `benchmark-results/maze-run-001-mock/` 아래입니다. 실제 실험의 입력 지문이나 재개 상태를 변경하지 않습니다. 점수·토큰은 합성 데이터이고 시간은 모의 프로세스의 소요 시간이므로 실제 모델 성능을 나타내지 않습니다. 추론 강도에 `unsupported`를 추가하면 미지원 오류 기록도 모의할 수 있습니다. 모의 실행의 점수는 어떤 실제 기능도 검증했다고 주장하지 않습니다.

실제 실행은 기존 CLI와 같은 안전 정책, 독립 채점, 완료 작업 건너뛰기를 사용합니다. 설정을 바꾼 뒤 기존 결과 폴더로 재개하면 일관성 검사에서 거부되므로 새 결과 폴더를 지정하세요. 창을 실행 중에 닫으면 먼저 중단·저장을 완료하고 종료하며, 저장하지 않은 편집 내용은 별도로 확인합니다. 이미 완료된 실행 실패/미지원은 재개 시에도 건너뜁니다.

## 실행과 재개

각 조합·반복에 안정적인 `job-...` ID를 부여하고, 실제 시도마다 UUID를 새로 발급합니다. 새 프로세스에서 `codex exec --json`을 실행하며 모델, 추론 강도, 승인 정책 `never`를 명시합니다. `resume`·`fork`·과거 대화 ID는 전달하지 않습니다. `--ephemeral`로 CLI 세션 기록 저장을 끄며, 공유 데몬을 끄는 옵션이 있으면 사용합니다. 사용자 설정 파일을 무시하는 `--ignore-user-config`는 인증 저장소 위치를 바꾸거나 인증 파일을 복사하지 않습니다.

처음 시작할 때 프롬프트, 시작 파일, 채점 플러그인 전체를 고정하고 SHA-256 해시와 설정 지문을 기록합니다. 모든 후보는 이 시작 파일 사본에서 시작합니다. 시작 파일의 `.git`, `.codex`와 심볼릭 링크·Windows junction·reparse point는 거부합니다. 후보 작업 폴더는 실행기·채점기·결과와 별도로 생성합니다.

`Ctrl+C`를 누르면 새 작업 예약을 중지하고 실행 중인 프로세스 트리를 종료한 후 보고서를 작성합니다. Windows Job Object의 kill-on-close를 사용하며 프로세스를 Job에 넣지 못하면 실행을 실패시킵니다. Unix에서는 별도 프로세스 그룹을 종료합니다. 프로세스 종료·컨테이너 정리·사본 작성·보고서 저장에는 설정 시간 외의 짧은 정리 시간이 필요할 수 있습니다. 전원 차단·프로세스 강제 종료에서는 마지막 저장 시점 이후의 메타데이터가 없을 수 있지만 이미 기록된 원본 로그는 남습니다.

같은 명령으로 재개할 때:

- `succeeded`, `failed`, `unsupported`, `timed_out`은 종료된 실험이므로 건너뜁니다. 종료된 실패를 같은 조건에서 다시 생성하려면 아래의 `--retry-failed`를 사용합니다.
- `pending`, `running`, `interrupted`, `grading`은 미완료 상태입니다. 생성이 완료되어 제출물 해시까지 저장되었으면 모델을 다시 호출하지 않고 채점만 이어갑니다. 변경된 제출물은 재채점하지 않습니다.
- 채점 중 전체 실행 시간 예산이 만료되면 `interrupted`로 보존하고 다음 실행에서 채점만 재개합니다. 채점기 자체의 `grader.timeout_seconds` 제한을 먼저 초과한 경우는 종료된 실패로 기록합니다.
- 생성 도중 중단되었으면 이전 로그·시도를 보존하고 동일 시작 파일에서 새 시도를 만듭니다. 모든 시도 이력은 JSON과 HTML에 남고, 조합 통계는 현재 시도 기준입니다.
- 설정·프롬프트·시작 파일·채점기 또는 고정 사본이 달라지면 기존 실험과 섞지 않고 재개를 거부합니다.
- 결과 폴더에 OS 파일 잠금을 걸어 동시에 두 실행기가 덮어쓰지 못하게 합니다. 저장은 임시 파일 교체로 수행합니다.

`--report-only`는 설정 파일의 `output_dir`로 결과 폴더를 찾고, 그 폴더에 저장된 `manifest.json`의 실험 목록과 실행 결과로 보고서를 다시 생성합니다. 설정의 모델·반복 수를 바꾸거나 원본 프롬프트·시작 파일·채점기를 이동한 뒤에도 저장된 실험 목록을 유지합니다. 상대 `output_dir`는 설정 파일의 폴더를 기준으로 해석합니다. 이 명령의 종료 코드 0은 보고서 생성 완료이며, 저장된 실험의 성공 여부와는 별개입니다.

실제 실행 명령의 종료 코드 0은 모든 실행과 채점 프로토콜의 정상 종료, 1은 종료된 실행 실패 포함, 2는 설정·환경 오류, 130은 중단/전체 시간 제한을 뜻합니다. **정상 종료는 기능 테스트 만점을 뜻하지 않습니다.** 기능 검증은 `grade.tests`, `score`, `pass_rate`로 판단합니다.

## 저장된 생성물 재채점

```powershell
python -m codex_bench --config config.local.json --regrade
```

`output_dir`의 manifest와 현재 결과가 가리키는 저장된 생성물을 사용합니다. Codex 진단·인증·모델 호출은 하지 않으며, 원본 프롬프트·시작 파일이나 현재 모델 목록도 필요하지 않습니다. 설정의 **현재 `grader.plugin_dir`과 `grader.options`**를 재채점마다 새 사본으로 보존하므로 수정된 채점기를 적용할 수 있습니다. 채점 시간 제한과 출력·사본 크기 제한도 현재 설정을 사용합니다. 실제 후보 실행이 필요한 플러그인은 기존과 같이 격리된 executor를 사용합니다.

해시가 기록된 제출물이 없어졌거나 바뀌었으면 재채점을 거부합니다. 저장된 생성물이 없는 미실행·조기 실패 작업은 건너뜁니다. 대상이 없으면 새 모델 호출이나 채점 없이 종료합니다.

이력은 `regrades/<재채점 ID>/`에 별도로 저장됩니다. `private/grader/`에는 새 채점기, `manifest.json`에는 채점기 해시와 설정, `runs/<작업 ID>/`에는 제출물 사본·채점 로그·새 결과와 직전 결과 `source_result.json`이 남습니다. 원래 `runs/<작업 ID>/attempts/`의 생성물·결과·로그와 실험 시작 때의 고정 입력은 변경하지 않습니다.

현재 결과와 요약 보고서는 최신 재채점을 반영하며, 원래 생성 시도의 ID·토큰·시간을 유지합니다. 재채점 이력은 생성 시도 이력과 분리해 보여 주므로 토큰 사용량을 중복 합산하지 않습니다. 원래 코드 생성이 실패했다면 재채점이 정상 완료되어도 생성 실패 상태를 성공으로 바꾸지 않습니다.

재채점 명령의 종료 코드 0은 선택한 생성물의 채점 프로토콜 완료, 1은 채점기 오류 포함, 2는 설정·저장 데이터 검증 오류, 130은 중단/전체 시간 만료입니다. 0점이나 미검증 항목이 있어도 프로토콜이 완료되면 종료 코드 0일 수 있으므로 점수와 테스트 상태를 함께 확인하세요. 중단된 재채점은 이력에 남기되 해당 작업의 이전 현재 결과를 교체하지 않습니다. 다시 `--regrade`를 실행하면 새로운 채점 이력을 추가합니다.

## 종료된 실패 재시도

```powershell
python -m codex_bench --config config.local.json --retry-failed
```

현재 상태가 `failed`, `unsupported`, `timed_out`인 작업만 선택하고, 공통 시작 파일에서 **새 모델 호출과 새 UUID 시도**를 시작합니다. 추가 Codex 사용량이 발생합니다. `succeeded`와 미완료 상태(`pending`, `running`, `grading`, `interrupted`)는 변경하지 않습니다. 기능 점수가 낮아도 실행 상태가 `succeeded`이면 재시도 대상이 아닙니다. 미완료 작업을 이어가려면 옵션 없는 일반 실행을 사용하세요.

기존 실험이 있어야 하며 설정·프롬프트·시작 파일·채점기의 지문 검사를 그대로 적용합니다. 새 시도에는 `attempt_kind=retry`, `retry_of_attempt_id`로 출처를 기록합니다. 과거 시도 파일은 그대로 두고 현재 결과만 새 시도로 갱신합니다. 대상이 없으면 0으로 종료하며, 대상이 있을 때 종료 코드 0/1은 선택된 재시도들의 성공/실패를 기준으로 합니다. 중단 시에는 130과 새 시도의 기록을 남깁니다.

`--regrade`와 `--retry-failed`는 서로 함께 사용할 수 없으며 `--gui`, `--doctor`, `--dry-run`, `--report-only`와도 각각 별도 명령으로 실행합니다.
