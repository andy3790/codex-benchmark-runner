## 일반 개발 검증

```powershell
python -m unittest discover -v
python tools/make_sample_report.py
python tools/check_repository.py
python -m pip wheel . --no-deps --wheel-dir dist
```

단위·모의 통합 테스트는 가짜 Codex 프로세스와 JSONL fixtures를 사용합니다. 순차/병렬 실행, stdout/stderr, 토큰 중복 방지, 누락값, 시간 제한, 프로세스 자식 종료, 중단·재개, 입력 지문, 독립 채점 프로토콜과 HTML escaping을 검사합니다. GUI 테스트는 Tk 위젯과 이벤트 루프를 사용하며 화면이 없는 호스트에서는 skipped가 될 수 있습니다.

미로 채점기 테스트에서 호스트 Node로 실행하는 JavaScript는 개발자가 작성한 신뢰 가능한 fixture와 오류 변형뿐입니다. 실제 제출 JavaScript는 Docker executor에서 실행합니다. Docker가 없는 경로에서는 동적 항목이 skipped로 남는지도 검사합니다.

합성 보고서는 형식 예시이며 실제 모델 성능이 아닙니다. 테스트 통과, 프로세스의 정상 종료, 제출물의 기능 점수는 서로 다른 지표입니다. 자동 채점 범위는 [미로 채점기 설명](../graders/maze/README.md)을 참고하세요.

## 2026-11-04 재채점·실패 재시도 기능 검증

Windows/Python 3.11.9에서 전체 테스트 **203개**를 스킵 없이 통과했습니다. 회귀 테스트 33개(재채점 17개, 실패 재시도 9개, CLI 통합 5개, 보고서 2개)를 추가했으며 저장소 공개 파일 검사와 `git diff --check`도 통과했습니다.

- `--regrade`는 현재 설정의 채점기·옵션을 새 사본으로 고정하고 저장된 생성물만 평가합니다. Codex 진단·명령 생성·모델 실행 경로를 금지한 CLI 통합 테스트에서도 동작합니다. 원본 프롬프트·시작 파일이 없고 모델 설정이 바뀐 경우, 수정된 채점기를 사용한 반복 재채점, 생성 토큰·원본 시도·과거 채점 사본 보존을 검사했습니다.
- 제출물 해시와 경로 검증, 복사 중 변경, 출력 잠금, 자기 자신을 포함하는 채점기 사본 경로 거부, 채점기 오류, 중단·전체 시간 제한을 검사했습니다. 중단된 재채점은 이력만 추가하고 이전 현재 결과를 유지합니다. 실제 신뢰 fixture worker로 새 채점기 사본과 옵션 적용도 검증했습니다.
- `--retry-failed`는 실패 3종만 새 생성 시도로 실행하고 성공·미완료 작업을 보존합니다. 이전 시도 파일의 해시, 새 UUID와 재시도 출처, 반복 재시도, 설정 변경 거부, 시작 전후 예외·중단의 이력 보존을 검사했습니다. 대상이 없으면 Codex 진단 없이 출력 파일도 그대로 유지합니다.
- 보고서의 재채점 이력과 생성 시도 이력을 분리하고 최신 점수·원본 토큰·채점 출처 링크를 검사했습니다. 별도 임시 폴더에서 기존 합성 예시의 8개 결과·시도와 빈 재채점 이력을 포함한 JSON·CSV·HTML 생성도 확인했습니다.

기존 로컬 실행 결과 335개는 해시가 일치하며 Git 추적 제외 상태를 유지합니다. 실제 모델이나 기존 실제 제출물은 실행하지 않았고, 후보 실행은 모의 프로세스와 신뢰 가능한 fixture만 사용했습니다.

## 2026-11-04 Docker·토큰·GUI 경계 처리 보완

Windows/Python 3.11.9에서 전체 테스트 **170개**를 스킵 없이 통과했습니다. 회귀 테스트 19개(Docker 2개, 토큰 이벤트 7개, GUI 모델 7개·Tk 통합 3개)를 추가했으며 저장소 공개 파일 검사와 `git diff --check`도 통과했습니다.

- 사전 검사에서 확인된 Docker 실행파일·엔진·이미지 미지원은 `skipped`를 유지합니다. 실행 요청 이후 종료 코드 `125/126/127`은 Docker 오류처럼 보이는 stderr와 함께 반환되어도 `error`이며, 샘플 채점에서 0/100점으로 집계됩니다. 미로 채점기도 공통 실행기의 판정을 사용합니다.
- 같은 turn의 사용량 없는 재전송은 측정값을 지우지 않고, 나중에 도착한 지표는 누락값만 보완합니다. 숫자가 충돌한 지표는 `null`로 유지하며 경고를 남깁니다. 누적값 우선순위, 다른 turn 합산, event ID 중복 제거를 유지합니다. 기존 로컬 이벤트 로그 51개를 이전 파서와 비교해 사용량과 집계 출처가 동일함을 확인했습니다.
- 새로 선택한 프롬프트는 선택 시점의 내용을 기준으로 외부 변경·삭제를 감지합니다. 파일 선택 취소·읽기 실패는 기존 기준을 유지합니다. 정상 편집 저장, 새 파일 생성, 반복 저장, 편집하지 않은 파일의 BOM·CRLF 보존을 검사했습니다. Tk 통합 테스트도 실제 위젯을 사용해 수행했습니다.

Docker는 프로세스 응답을 모의하여 검증했으며 실제 모델이나 기존 제출물은 실행하지 않았습니다. 로컬에 보존한 실행 결과 335개는 이전 해시와 일치하고 Git 추적에서도 제외되어 있습니다.

## 2026-11-04 결과 보존·복구 수정 검증

Windows/Python 3.11.9에서 단위·모의 통합 테스트 **151개**를 통과했습니다. 기존 138개에 보고서 재생성 7개, 채점 제한시간·재개 3개, 미로 부분 실패 처리 3개의 회귀 테스트를 추가했습니다.

- 보고서는 현재 모델 설정 대신 저장된 manifest의 실험 목록으로 재생성합니다. 원본 프롬프트·시작 파일·채점기가 없거나 설정의 모델·반복 수가 달라져도 저장된 완료·미완료 결과를 유지합니다. 잘못된 manifest나 결과 데이터는 기존 JSON·CSV·HTML을 교체하기 전에 거부합니다.
- 채점 중 전체 실행 시간 예산이 만료되면 종료 코드 130과 재개 가능한 상태를 보존하고, 다음 실행에서 생성물을 재사용해 채점만 수행합니다. 채점기 자체 제한시간 초과는 종료된 실패로 유지합니다.
- 미로의 일부 추가 통로 생성 호출이 예외 또는 잘못된 반환값을 내면 관련 항목만 실패로 기록하고 나머지 채점을 계속합니다. 정상 fixture의 90/90점, 계획 100점, 미검증 7개를 유지합니다.

실행 결과 파일 335개는 로컬에 보존하면서 Git 추적만 해제했습니다. 변경 전후 SHA-256 일치와 무시 규칙 적용을 확인했고, 저장소 공개 파일 검사와 `git diff --check`를 통과했습니다. 기존 로컬 실험 manifest 11개의 51개 작업을 새 로더로 읽었으며 원본 결과 파일은 변경하지 않았습니다. 별도 임시 폴더에서 합성 보고서 8개 결과의 JSON·CSV·HTML과 시도 이력 생성도 확인했습니다. 실제 모델 호출과 Docker에서의 실제 제출물 재실행은 하지 않았습니다.

CLI는 실제 적용 모델/추론 메타데이터를 제공하지 않아 `observed_configuration`은 비어 있습니다. 요청값과 실행 명령은 따로 보존했습니다. 생성 중 일부 셸 시도의 실패도 원본 로그에 남겼으며, 선택된 PowerShell·Node의 실행은 수정한 권한 프로필에서 별도 모델 없는 검사로 확인했습니다.

PowerShell snapshot 경고를 미지원 오류로 오인한 분류 버그는 원본 이벤트(종료 코드 0, turn.completed, 오류 이벤트 없음)를 재파싱해 바로잡았습니다. 수정 전 결과와 수정 이유를 보존했으며 재분류에 추가 모델 호출은 사용하지 않았습니다.

이 실제 실행의 원본 로그·생성물·개인 경로는 로컬 `benchmark-results/`에만 보관하며 저장소에는 포함하지 않습니다. 이 기록은 단일 실행의 관측 결과로 모델 순위를 뜻하지 않습니다. 실제 생성물의 브라우저 UI 조작과 보고서 화면의 자동 캡처는 검증하지 않았습니다. Python 3.12와 Ubuntu 검증은 CI 워크플로에 구성되어 있으며, 원격 실행 결과는 GitHub Actions에서 확인합니다.
