# 미로 과제 독립 채점기

`maze_prompt.md`의 **공개 API 계약**을 기준으로 검사합니다. Python 표준 라이브러리로 정답을 계산하며, 제출 JavaScript는 네트워크가 없는 읽기 전용 Docker Linux 컨테이너 안에서만 실행합니다. 유료 API나 추가 모델을 호출하지 않습니다. 제출물의 자체 테스트 결과를 독립 검증 점수로 사용하지 않습니다.

## 사용법

기본 공개 `config.json`은 `maze_prompt.md`, 채점기 `graders/maze`, 이미지 `node:22-bookworm-slim`을 연결합니다. 한 조합 예시는 `examples/config.maze-sol-low.json`에 있습니다. 최초 이미지 준비는 사용자가 다음 명령으로 할 수 있습니다. 실행기는 이미지를 자동 다운로드하지 않습니다.

```powershell
docker pull node:22-bookworm-slim
```

이후 GUI 또는 CLI에서 실험을 실행하면 제출물마다 이 채점기가 적용됩니다. 기존 결과와 섞이지 않게 새 결과 폴더를 지정하세요. 기존 실제 단일 실행의 측정 범위와 한계는 [검증 기록](../../docs/validation.md)에 있습니다.

이미 생성한 프로젝트는 모델을 다시 호출하지 않고 단독으로 채점할 수 있습니다.

```powershell
python tools/grade_maze.py "C:\bench\some-project" --output "benchmark-results\maze-regrade-01"
```

입력은 `index.html`과 `maze-core.js`가 있는 **프로젝트 폴더**입니다. 실행기의 결과를 채점할 때는 `runs/<job>/attempts/<id>/submission`을 지정하세요. 원본을 변경하지 않도록 새 사본에서 채점하며, 출력 폴더는 입력과 겹치면 안 됩니다. `report.html`, `results.json`, `results.csv`, 고정 채점기, 제출 사본과 실행 로그를 보존합니다. 이미 사용한 출력 폴더에 덮어쓰지 않습니다.

`--image`, `--test-timeout`(기본 5초/배치), `--timeout`(기본 전체 120초)을 지정할 수 있습니다. Docker가 없거나 엔진/이미지가 준비되지 않았다면 동적 검사는 `skipped`, 해당 점수는 `null`입니다. 호스트에서 제출 코드를 실행하는 우회 모드는 제공하지 않습니다. 종료 코드 0은 채점 프로토콜 완료이며 미검증 항목까지 통과했다는 의미가 아닙니다. 실제 실패가 있으면 1, 채점기 오류는 2, 중단은 130입니다.

## 배점: 계획 만점 100점

| 범주 | 점수 | 실제 검사 |
| --- | ---: | --- |
| 산출물·문서 | 10 | index/core 파일, README·자체 테스트 소스 **존재**, 정적 로컬 자원 참조, 하드코딩된 외부 의존성 |
| API | 5 | CommonJS API 실행 3점, classic-script VM의 `window.MazeCore` 생성·탐색 실행 2점 |
| 생성 | 30 | DFS·Prim 각각 표현/기본 비용/외곽 벽 1.5, 벽 양방향 2, 1셀·1행·1열 0.5, 연결성 3, Perfect Maze 3, 시드 재현성 2, 추가 통로 1.5, 가중치 1.5 |
| 탐색·상태 | 40 | BFS 최단 이동 7, Dijkstra 최소 비용 7, A* 최소 비용 7, BFS 실제 진입 비용 4, 도달 불가 3, 동일 시작/끝 3, 입력 불변성 4, 확장 순서 3, 재실행 일관성 2 |
| 성능 | 5 | 80×80 가중 순환 미로의 생성·BFS/Dijkstra/A* 정확성과 함수당 2,000ms 예산 |
| 브라우저 UI | 10 | 실제 브라우저 검증이 없어 **항상 미검증**, 아래 5개 항목에 각 2점 배정 |

일반적인 CommonJS/UMD 제출물에서 자동 측정 가능한 만점은 **90점**, 계획 만점은 **100점**입니다. UI를 구현하지 않아도 미검증 10점을 성공으로 주거나, 자동 90점을 100점으로 환산하지 않습니다. 실제 HTML 로딩이 필요한 ESM 제출물의 browser API를 VM이 확인하지 못하면 2점도 skipped이므로 자동 측정 만점은 88점일 수 있습니다. 보고서의 `max_score`, `planned_max_score`, `skipped_tests`를 함께 읽으세요. Docker가 없으면 정적 10점만 측정될 수 있습니다.

## 검사 내용과 해석

- 벽 비트는 북/동/남/서 1/2/4/8입니다. 외곽 통로·비대칭 벽·잘못된 셀 수·범위 밖 비용을 거부합니다.
- DFS와 Prim 모두 여러 직사각형과 0/최대 uint32/일반 시드로 검사합니다. 작은 크기는 1×1, 1×7, 7×1입니다. UI 최대 크기는 프롬프트에 수치가 정해져 있지 않아 임의의 상한을 채점 기준으로 강제하지 않습니다.
- Perfect Maze는 전체 연결 + 무방향 간선 V−1을 검사합니다. 추가 통로는 **전체 내부 벽 중 기본 트리에서 남은 벽**에 대한 비율이며, 정수화는 floor/ceil 모두 허용합니다. `loops=1`은 남은 벽을 모두 열어야 합니다. 서로 다른 옵션 사이의 특정 미로 모양이나 경로를 강제하지 않습니다.
- 가중치 없는 미로는 모든 비용 1, 가중 미로는 정수 1..9입니다. 다수 셀인 가중 사례에서 실제 비용 변화도 확인합니다. 같은 시드·옵션을 다른 호출 사이에 끼워 반복해 전역 난수 상태 누출을 검사합니다. 생성 모양·비용 이외의 추가 시간 메타데이터는 재현성 비교에서 제외합니다.
- 탐색에는 가중 우회로, 출발/도착 비용 방향 차이, 비구석 시작/끝, 완전 단절, 동일 시작/끝과 고정 시드로 만든 16개 임의 그래프를 사용합니다. Python BFS/heap 기반 Dijkstra로 최적값을 **호스트에서** 계산합니다. 기대 경로나 정답 비용은 컨테이너에 주지 않습니다.
- 경로의 각 이동은 실제 열린 상하좌우 간선이어야 합니다. 진입 셀 비용만 합산하고 시작 비용은 제외합니다. 동점 경로는 어떤 최적 경로든 인정합니다. BFS는 이동 횟수로, Dijkstra/A*는 실제 총 비용으로 판정하므로 가중 미로에서 BFS를 최소 비용 알고리즘으로 오인하지 않습니다.
- `visitedOrder`는 인덱스 유효성·시작점·확장된 frontier와의 연결, BFS/Dijkstra 거리 순서를 검사합니다. 모든 구현에 특정 이웃 순서나 동일한 방문 셀 개수를 강요하지 않습니다. 시작=끝을 즉시 반환하는 경우 빈 확장 순서도 허용합니다.
- 탐색 전후 전체 입력 데이터를 비교해 벽·비용 변경을 탐지합니다. 같은 입력 반복 시 비교하는 반환값은 명시된 `found/path/visitedOrder/cost`뿐이며 추가 계산 시간 필드는 비교하지 않습니다.
- 성능 측정은 **순수 동기 함수 호출**을 `performance.now()`로 측정합니다. Docker 시작·입력 복제·JSON 직렬화·시각화 애니메이션은 함수 시간에서 제외합니다. 한 배치 전체에는 별도 프로세스 시간 제한이 있어 로딩/무한 루프도 중단됩니다. 절대 2,000ms는 모델 순위 자체가 아니라 과제용 검사 예산이며 CPU·호스트 부하에 따라 달라집니다.
- 정적 자원 검사는 HTML src/href, CSS url/import, JS의 리터럴 import/require/fetch 경로 등을 확인합니다. Node 기본 모듈을 사용하는 자체 테스트는 허용합니다. README의 외부 링크와 보통의 코드 주석을 외부 런타임 의존성으로 채점하지 않습니다. 소스 스캔 예산은 8 MiB이며 이를 넘으면 추정 통과 대신 skipped 처리합니다.

## 자동으로 확인했다고 주장하지 않는 항목

다음 브라우저 UI 5개는 각 2점의 skipped 항목으로 남습니다.

1. 실제 Chrome에서 `file://index.html` 오프라인 실행
2. 필수 조작 및 알고리즘 비교표·이전 비교 결과 무효화
3. 애니메이션, 일시정지/재개, Step, 취소·초기화의 실제 동작
4. 반응형 Canvas, 색상 범례와 상태별 시각 구분
5. 생성 중 UI 응답성과 이전 비동기 실행이 새 상태를 덮어쓰지 않는지

Node의 browser namespace 검사는 DOM 없는 VM 호환성 검사이며 Chrome을 실행한 결과가 아닙니다. ESM/inline bootstrap 등의 브라우저 로딩 흐름이 지원되지 않으면 browser API 항목을 skipped로 둡니다.

출력 그래프의 성질만으로는 DFS와 Prim이 실제로 다른 알고리즘으로 작성됐는지, A*가 실제로 허용 가능한 Manhattan 휴리스틱을 쓰는지 증명할 수 없습니다. 이 둘은 별도의 **0점 수동 검토 항목**으로 남습니다. 입력 오류 정책, UI 최대 크기, 코드 가독성·중복·외부 라이브러리의 소스 내 포함 여부도 수동 검토가 필요합니다. 독립 알고리즘 검사는 실제로 실행되지만 이러한 미검증 사항까지 완성됐다고 표시하지 않습니다.

## 격리와 보존

고정된 `plugin.py`와 `bridge.js`는 제출 폴더에 복사하지 않습니다. 제출물 하나만 `/submission`에 읽기 전용으로 마운트하고 Docker 네트워크/루트 쓰기/권한을 제한합니다. 테스트 입력과 **정답 없는 호출 어댑터**만 stdin/명령 인수로 주고, 기대값과 점수 계산은 호스트에 둡니다. 기존 workspace restricted 정책으로 개발 과정에서도 채점기 읽기를 차단하세요.

4개 배치(generation, search, browser_namespace, large_grid)의 stdout/stderr와 채점에 전달한 반환값은 `grading/codex-bench-*/`에 보존합니다. 대형 격자 배치는 정확성 검사에 필요한 필드만 반환하며, 불필요한 애니메이션 기록과 입력 사본은 전송하지 않습니다. 1MiB 출력 제한과 실제 함수 호출 대상은 그대로 유지합니다. `maze-executions.json`에는 배치 소요 시간, `maze-compute-times.json`에는 함수별 ms가 기록됩니다. 컨테이너/JSON/API 오류는 실패이며, Docker 엔진/이미지가 없는 등 지원되지 않는 실행 환경만 미검증입니다.

채점기 자체 검증:

```powershell
python -m unittest tests.test_maze_grader -v
```

호스트 Node는 이 테스트에서 **직접 작성한 신뢰 가능한 fixture와 의도적인 오류 변형만** 실행합니다. 모델 결과를 호스트에서 실행하는 설정은 없습니다. 올바른 fixture의 90/90·UI 미검증뿐 아니라 비용 계산 오류, BFS로 대체한 가중 탐색, 입력 변조, 추가 통로/가중치 무시, 외곽 벽 누락, 잘못된 응답·실행 환경 미지원 등을 검사합니다. fixture는 `starter/`에 넣지 않아 벤치마크 대상에 정답 구현을 주지 않습니다.
