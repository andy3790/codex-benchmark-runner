# 개발 과제: 미로 생성 및 경로 탐색 시각화 프로그램

## 1. 프로젝트 목표

다양한 미로 생성 알고리즘과 경로 탐색 알고리즘을 시각적으로 비교하고 실험할 수 있는 인터랙티브 웹 애플리케이션을 개발한다.

단순한 알고리즘 데모가 아니라, 사용자가 미로를 생성하고 설정을 변경하며 탐색 과정을 관찰하고 결과를 비교할 수 있는 완성도 높은 프로그램을 목표로 한다.

주어진 요구사항을 충족하는 실제 실행 가능한 프로그램을 구현하라. 설계 문서만 작성하는 것으로 작업을 종료하지 않는다.

## 2. 개발 환경 및 제약

- HTML5, CSS3, JavaScript 사용
- Vanilla JavaScript 기반
- 외부 라이브러리, 프레임워크, CDN, 외부 API 사용 금지
- 유료 리소스 및 외부 이미지 사용 금지
- 인터넷 연결 없이 실행 가능
- Chrome 기반 최신 브라우저 지원
- 별도 빌드 과정 없이 `index.html`을 열어 실행 가능
- 핵심 알고리즘은 UI 코드와 분리
- 테스트에 Node.js 기본 기능을 사용할 수 있으나 npm 패키지 설치는 금지
- 작업 폴더 외부의 파일을 변경하지 말 것

파일 구조 및 세부 아키텍처는 자유롭게 결정하되, 코드의 유지보수성과 확장성을 고려한다.

## 3. 미로 생성 기능

다음 두 알고리즘을 구현한다.

### A. Randomized DFS (Recursive Backtracker)

깊이 우선 탐색 기반의 미로 생성 알고리즘.

### B. Randomized Prim

무작위 프림 알고리즘 기반의 미로 생성 알고리즘.

### 공통 요구사항

- 격자 기반 미로
- 미로의 가로·세로 크기 변경
- 난수 시드 지정 가능
- 동일한 알고리즘, 크기, 시드 및 옵션에서는 동일한 미로 생성
- 외부 라이브러리에 의존하지 않는 결정적 난수 생성기 사용
- 생성 과정 시각화
- 생성 완료 후 시작점에서 도착점까지 이동 가능한 미로 생성
- 기본 생성 모드는 모든 셀이 연결되고 두 셀 사이에 경로가 정확히 하나인 Perfect Maze
- 추가 통로를 열어 순환 경로가 존재하는 미로를 만드는 옵션 제공
- 미로 생성 중에도 애플리케이션의 기본 인터페이스가 응답해야 함

미로는 각 셀과 인접 셀 사이의 벽 유무로 표현한다. 벽은 반드시 양방향으로 일관되어야 하며 격자 바깥으로 연결되어서는 안 된다.

## 4. 경로 탐색 기능

다음 세 알고리즘을 구현한다.

### A. BFS

너비 우선 탐색. 이동 비용을 고려하지 않고 최소 이동 횟수의 경로를 탐색한다.

### B. Dijkstra

셀별 이동 비용을 고려해 최소 비용 경로를 탐색한다.

### C. A*

맨해튼 거리 기반의 허용 가능한 휴리스틱을 사용해 최소 비용 경로를 탐색한다.

### 공통 요구사항

- 시작점과 도착점 지정 가능
- 방문한 셀을 순서대로 시각화
- 탐색 완료 후 최종 경로 강조
- 탐색 과정 일시정지 및 재개
- 1단계씩 진행하는 Step 기능
- 시각화 속도 조절
- 탐색 초기화 및 재실행
- 알고리즘 변경 후 동일한 미로에서 재탐색
- 경로가 없는 경우 정상적으로 처리
- 시작점과 도착점이 동일한 경우 정상적으로 처리

### 이동 비용 규칙

- 각 셀의 이동 비용은 1~9의 정수
- 초기 기본 비용은 1
- 옵션으로 이동 비용을 무작위 배정할 수 있어야 함
- 비용은 출발 셀이 아닌 도착 셀에 진입할 때 지불
- 시작 셀의 비용은 0으로 계산
- 상하좌우 네 방향으로만 이동 가능
- 대각선 이동 금지
- 벽을 통과할 수 없음

BFS는 최소 이동 횟수를 보장해야 한다.

Dijkstra와 A*는 최소 총 이동 비용을 보장해야 한다.

동일한 미로에서 Dijkstra와 A*의 최적 경로 비용은 항상 같아야 한다. 동점인 최적 경로가 여러 개일 때 경로 자체는 달라도 된다.

가중치가 있는 경우 BFS가 최소 비용을 보장하지 않는다는 점을 사용자에게 명확히 표시한다.

## 5. 사용자 인터페이스

사용자가 별도의 설명 없이도 기본적인 기능을 사용할 수 있는 UI를 설계한다.

### 필수 조작

- 미로 생성 알고리즘 선택
- 경로 탐색 알고리즘 선택
- 미로 가로·세로 크기 설정
- 난수 시드 입력
- 미로 생성 버튼
- 시작점 및 도착점 변경
- 추가 통로 생성 비율 조절
- 가중치 활성화 및 비활성화
- 탐색 시작 버튼
- 일시정지 및 재개
- 한 단계 진행
- 속도 조절
- 초기화 버튼

### 시각화

Canvas 기반 2D 시각화를 권장한다.

최소한 다음 상태를 시각적으로 구분해야 한다.

- 벽
- 일반 통로
- 시작점
- 도착점
- 탐색 대기
- 방문한 셀
- 최종 경로
- 현재 탐색 중인 셀

상태별 색상 범례를 제공한다.

화면 크기가 변경되어도 미로의 비율이 유지되어야 한다.

미로가 큰 경우에도 조작과 시각화가 가능한 구조로 구현한다.

## 6. 알고리즘 비교 기능

탐색이 완료되면 다음 정보를 표시한다.

- 실행한 알고리즘
- 탐색 성공 여부
- 총 방문 셀 수
- 최종 경로 길이(이동 횟수)
- 최종 경로 비용
- 순수 탐색 계산 시간(ms)

시각화 애니메이션에 소비된 시간은 알고리즘 계산 시간에서 제외한다.

사용자가 동일한 미로에 대해 BFS, Dijkstra, A*를 각각 실행한 결과를 비교할 수 있는 표를 제공한다.

미로 또는 이동 비용이 변경되면 이전 비교 결과를 현재 결과와 혼동하지 않도록 초기화하거나 별도 표시한다.

## 7. 상태 관리 및 예외 처리

다음 상황을 정상적으로 처리해야 한다.

- 생성 중 다시 생성 버튼을 누르는 경우
- 탐색 중 알고리즘을 변경하는 경우
- 탐색 중 미로를 초기화하는 경우
- 탐색 중 시작점이나 도착점을 변경하는 경우
- 탐색 완료 후 재실행하는 경우
- 빠른 속도로 여러 번 버튼을 누르는 경우
- 탐색 가능한 경로가 없는 경우
- 최소·최대 크기의 미로
- 시작점과 도착점이 같은 경우
- 브라우저 창 크기 변경

이전 실행의 비동기 애니메이션이 새로운 미로나 탐색 상태를 변경하지 않도록 해야 한다.

동일한 입력 조건에서는 동일한 계산 결과가 나와야 한다.

## 8. 독립 테스트 가능한 핵심 API

자동화된 외부 검증을 위해 핵심 알고리즘을 UI에 의존하지 않는 순수 JavaScript 모듈로 구현한다.

`maze-core.js`에서 다음 인터페이스를 제공한다.

### generateMaze(options)

입력 예시:

```javascript
{
  width: 20,
  height: 20,
  algorithm: "dfs",
  seed: 12345,
  loops: 0,
  weighted: false
}
```

- `algorithm`: `"dfs"` 또는 `"prim"`
- `seed`: 부호 없는 32비트 정수
- `loops`: 0~1 사이 값. 기본 미로 생성 후 남아 있는 내부 벽 중 추가로 개방할 비율
- `weighted`: true일 경우 시드에 따라 셀별 비용 1~9 배정

반환 데이터:

```javascript
{
  width: 20,
  height: 20,
  cells: [
    { walls: 15, cost: 1 }
  ]
}
```

`cells`는 행 우선 순서의 1차원 배열이며 인덱스는 `y * width + x`로 계산한다.

벽 비트마스크:

- 북쪽: 1
- 동쪽: 2
- 남쪽: 4
- 서쪽: 8

비트가 설정되어 있으면 해당 방향에 벽이 있다는 의미다.

### solveMaze(maze, options)

입력 예시:

```javascript
{
  algorithm: "astar",
  start: 0,
  end: 399
}
```

지원 알고리즘:

- `"bfs"`
- `"dijkstra"`
- `"astar"`

반환 데이터:

```javascript
{
  found: true,
  path: [0, 1, 2],
  visitedOrder: [0, 1, 2],
  cost: 2
}
```

- `path`: 시작점부터 도착점까지 순서대로 이어진 셀 인덱스
- `visitedOrder`: 실제 탐색에서 확장한 셀 인덱스의 순서
- `cost`: 최종 경로에서 시작 셀을 제외한 진입 비용의 합계
- 경로가 없으면 `found: false`, `path: []`, `cost: null`
- 시작점과 도착점이 동일하면 길이 1인 경로와 비용 0을 반환

BFS의 `cost`도 반환된 경로의 실제 셀 진입 비용 합계로 계산한다.

### 모듈 접근

브라우저에서 `window.MazeCore`로 접근할 수 있어야 하며, Node.js에서는 `require("./maze-core.js")`로 사용할 수 있어야 한다.

각 함수는 UI에 의존해서는 안 된다.

## 9. 자동 테스트

외부 테스트 라이브러리 없이 핵심 알고리즘을 검증하는 테스트 코드를 작성한다.

최소 검증 항목:

1. DFS 미로의 전체 연결성
2. Prim 미로의 전체 연결성
3. Perfect Maze의 사이클 부재
4. 벽의 양방향 일관성
5. 난수 시드 재현성
6. BFS의 최단 이동 횟수
7. Dijkstra의 최소 비용 경로
8. A*와 Dijkstra의 최적 비용 일치
9. 도달 불가능한 경로
10. 시작점과 도착점이 같은 경우
11. 여러 크기와 시드에서의 알고리즘 동작
12. 입력 미로 데이터가 탐색 함수 호출에 의해 변경되지 않는지 확인

테스트는 실행 방법을 문서화하고 반복 실행할 수 있어야 한다.
